Reports varlock-specific problems in .env.schema and the .env files layered with it. Active only with Settings | Tools | EnvBridge | varlock compatibility mode on, and only in directories with a .env.schema or in files that use decorators or function values, for example: 
# @plugin(@varlock/1password-plugin)
# @initOp(token=$OP_TOKEN)
# @currentEnv=$APP_ENV
# ---
# @type=enum(dev, prod)
APP_ENV=dev
API_KEY=op(op://vault/api/key)

Reported: deprecated decorators (with what replaces them) and bare /regex/ type options, unknown functions, functions of a plugin (op(), infisical(), vaultSecret()) that no header loads with @plugin(…) or its @init… decorator, $KEY / ref(KEY) references to keys no layered file defines, an @currentEnv naming a missing key, @import of a file that doesn't exist (unless allowMissing=true), and plain values that don't match a @type declared in another layer, such as an invalid enum value in .env for an enum of .env.schema.

General decorator problems are reported by env-spec decorators in .env files. Nothing is evaluated: functions such as exec() and plugin functions are only checked by name.
